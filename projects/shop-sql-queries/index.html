Project 2: Answer Business Questions with SQL

IntermediateAbout 1 to 2 hours (estimate)

Unofficial study resource. Independent practice material, not affiliated with any software vendor.

A fictional shop keeps customers, products and orders (2024 and 2025) in three tables. Load the data and answer eight questions with SQL. For joins, grouping and window functions, see the SQL study guide.

Set up

Synthetic data Every file here was generated by a seeded script. It describes no real company, person or sale, and the products and customer IDs are made up.

Download shop.sql. It creates three tables and inserts the rows (80 customers, 12 products, 1,000 orders). With the SQLite command-line tool:

sqlite3 shop.db < shop.sql

Or with Python, which includes SQLite:

python3 -c "import sqlite3; c = sqlite3.connect('shop.db'); c.executescript(open('shop.sql').read())"
TableColumns
customersCustomerID, Region, Segment
productsProductID, Product, Category, UnitPrice
ordersOrderID, OrderDate (YYYY-MM-DD text), CustomerID, ProductID, Quantity, Discount

Revenue for an order is Quantity × UnitPrice × (1 − Discount). The solutions are written for SQLite; date functions and some syntax differ in other databases.

Tasks

Try each query yourself before you open the solution. Your result should match the expected rows, including the order.

Task 1: Orders per region

Count the orders placed by customers in each region, largest first.

Show a solution and the expected result 
SELECT c.Region, COUNT(*) AS orders
FROM orders o
JOIN customers c ON c.CustomerID = o.CustomerID
GROUP BY c.Region
ORDER BY orders DESC, c.Region;

Task 2: Revenue by category

Total revenue (quantity x unit price x (1 - discount)) per product category, rounded to 2 decimals.

Show a solution and the expected result 
SELECT p.Category, ROUND(SUM(o.Quantity * p.UnitPrice * (1 - o.Discount)), 2) AS revenue
FROM orders o
JOIN products p ON p.ProductID = o.ProductID
GROUP BY p.Category
ORDER BY revenue DESC;

Task 6: Average order value by segment

Average revenue per order for each customer segment, rounded to 2 decimals.

Show a solution and the expected result 
SELECT c.Segment, ROUND(SUM(o.Quantity * p.UnitPrice * (1 - o.Discount)) / COUNT(*), 2) AS avg_order_value
FROM orders o
JOIN customers c ON c.CustomerID = o.CustomerID
JOIN products p ON p.ProductID = o.ProductID
GROUP BY c.Segment
ORDER BY avg_order_value DESC;

Task 7: Running total by month, 2025

Monthly revenue for 2025 with a cumulative running total (a window function; needs SQLite 3.25 or later).

Show a solution and the expected result 
WITH monthly AS (
  SELECT strftime('%Y-%m', o.OrderDate) AS month, SUM(o.Quantity * p.UnitPrice * (1 - o.Discount)) AS revenue
  FROM orders o
  JOIN products p ON p.ProductID = o.ProductID
  WHERE o.OrderDate >= '2025-01-01' AND o.OrderDate < '2026-01-01'
  GROUP BY month
)
SELECT month, ROUND(revenue, 2) AS revenue, ROUND(SUM(revenue) OVER (ORDER BY month), 2) AS running_total
FROM monthly
ORDER BY month;

Task 8: Categories above a revenue threshold

Categories whose total revenue is more than 21,000.

Show a solution and the expected result 
SELECT p.Category, ROUND(SUM(o.Quantity * p.UnitPrice * (1 - o.Discount)), 2) AS revenue
FROM orders o
JOIN products p ON p.ProductID = o.ProductID
GROUP BY p.Category
HAVING SUM(o.Quantity * p.UnitPrice * (1 - o.Discount)) > 21000
ORDER BY revenue DESC;

How the answers were checked

Every solution above was executed against the downloadable shop.sql in SQLite 3.53.1 and the expected results come from those runs. A separate check recomputed the totals with exact decimal arithmetic. Other database systems may format or round results slightly differently.

Stretch ideas
