JavaScript Fundamentals: Key Concepts Explained

14 min read 20 Questions Published Aug 28, 2026 Reviewed Oct 18, 2026

Unofficial study resource. Written independently of any exam provider, employer or software vendor.

JavaScript interviews and skills tests lean heavily on language fundamentals. Questions about output, scope, and type coercion are common — framework knowledge matters far less.

Core topics to know

  • var vs let vs const — scoping, hoisting, and the temporal dead zone
  • Type coercion — == vs ===, truthy/falsy values
  • Closures — what they are and how they capture variables
  • Arrow functions — lexical this (no own this binding)
  • Promises & async/await — order of execution, .then() chaining
  • Array methods — map, filter, reduce, find, and what each returns
  • Objects — destructuring, spread, this in methods

Truthy and falsy values

Memorize the falsy values — everything else is truthy:

false, 0, -0, 0n, "", null, undefined, NaN

Tricky truthy values: "0", "false" (non-empty strings), [] and {} (empty objects are truthy!).

Classic trap [] == false is true (array coerces to empty string, which coerces to 0), but [] ? "yes" : "no" is "yes" because [] is truthy in a boolean context.

Async execution order

Expect questions like "what order do these logs appear?" Remember: synchronous code first, then microtasks (promises), then macrotasks (setTimeout):

console.log("1");
setTimeout(() => console.log("2"));
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2

Closures and the value of this

A closure is a function together with the variables from the place where it was created. The function keeps access to those variables even after the outer function has returned. Closures give you private state and are behind callbacks, event handlers and many module patterns.

function makeCounter() {
  let n = 0;
  return () => ++n;
}
const a = makeCounter();
a(); a();          // 1, then 2
const b = makeCounter();
b();               // 1  (separate n)

Each call to makeCounter creates a fresh n, so the two counters do not interfere. The classic loop question tests the same idea. With var, one variable is shared by the whole function, so callbacks created in the loop all see its final value. With let, each iteration gets its own binding.

for (var i = 0; i < 3; i++) setTimeout(() => console.log(i));   // 3 3 3
for (let j = 0; j < 3; j++) setTimeout(() => console.log(j));   // 0 1 2

this is decided by how a function is called, not where it is written, except for arrow functions. The rules, in practice:

  • obj.method(): this is obj.
  • A plain call fn(): this is undefined in strict mode (modules and classes are strict), otherwise the global object.
  • fn.call(x), fn.apply(x), fn.bind(x): this is x.
  • new Fn(): this is the new object.
  • Arrow function: no this of its own; it uses the one from the surrounding code.

The common bug is detaching a method: const f = obj.method; f() loses obj. The same happens when you pass obj.method as a callback. Fix it with obj.method.bind(obj) or by wrapping it in an arrow function. Do not use an arrow function as an object method that needs this to be the object, because it will pick up the outer this instead.

Equality and coercion without memorising tables

You do not need to memorise every == result if you remember how it works. === compares type and value with no conversion. == first converts operands when their types differ, mostly towards numbers. Two special cases are worth knowing: null == undefined is true, and neither equals anything else under ==, so null == 0 is false.

ExpressionResultWhy
"5" == 5truestring converted to number

To test for NaN use Number.isNaN(x) or Object.is(x, NaN). Prefer === by default. One idiom where == null is deliberate is checking "null or undefined" in one go, and many teams allow that single exception.

Truthiness bugs hide behind ||. In const port = config.port || 3000, a legitimate port of 0 is falsy and gets replaced. The nullish operator ?? only falls back on null or undefined, so config.port ?? 3000 keeps the 0. Likewise, ?. stops and returns undefined when it meets null or undefined, instead of throwing.

Debugging tip When a comparison surprises you, log typeof of both sides first. Values read from inputs, query strings and JSON often arrive as strings even when they look like numbers.

The event loop: how await fits in

JavaScript runs your code on a single thread. Waiting work (timers, network, events) is handled by the environment, and when it finishes, a callback is queued. After the current synchronous code ends, the engine first runs all queued microtasks (promise reactions and queueMicrotask), including any that those microtasks add, and only then takes the next macrotask such as a timer callback. This is why a long chain of promises can delay a setTimeout(..., 0), and why an endless microtask loop freezes the page.

await is promise syntax in disguise. The code before the first await runs synchronously; the rest of the function becomes a microtask continuation that resumes once the awaited promise settles. Predict this output:

async function f() {
  console.log("a");
  await null;
  console.log("b");
}
console.log("1");
f();
setTimeout(() => console.log("t"));
console.log("2");
// 1, a, 2, b, t

Walk through it: "1" prints; f() runs synchronously and prints "a", then pauses at await and returns; the timer is registered; "2" prints; the stack empties, so the microtask runs and prints "b"; finally the timer macrotask prints "t".

A typical interview follow-up is to explain why await inside a plain for loop runs requests one after another, whereas starting all promises first and passing them to Promise.all runs them concurrently. Be ready to say which you need: sequential when each step depends on the previous, concurrent when they are independent.

Promise and async error handling

Errors in promise code travel along the chain until something handles them. A .catch() at the end of a chain catches a rejection from any earlier step, and the same applies to a try/catch around await. A throw inside an async function becomes a rejected promise rather than a synchronous exception, so a try/catch around the call alone does not catch it unless you await it.

async function loadUser(id) {
  try {
    const res = await fetch("/api/users/" + id);
    if (!res.ok) throw new Error("HTTP " + res.status);
    return await res.json();
  } catch (err) {
    console.error("loadUser failed:", err.message);
    throw err;            // let the caller decide too
  }
}

Three mistakes appear again and again:

  • Trusting fetch to reject on 404 or 500. It only rejects on network failure; always check res.ok.
  • Forgetting await. You get a pending promise instead of the value, and a later rejection may go unhandled.
  • Using async callbacks in forEach. forEach ignores the promises its callback returns, so nothing waits. Use a for...of loop with await, or Promise.all(items.map(...)).

Choosing a combinator: Promise.all rejects as soon as any input rejects ("fail fast"). Promise.allSettled always waits and reports each outcome as fulfilled or rejected, which suits batches where partial success is fine. Promise.race settles with the first input to settle, handy for timeouts.

When you debug a rejected promise, read the stack trace from the bottom up to find the first await or .then that was involved, and add a .catch or try/catch there while you investigate. Browsers and Node both report rejections that nobody handled, so treat that warning as a real bug rather than noise. Also remember that .finally() runs whether the promise fulfilled or rejected, which makes it the right place to hide a loading spinner.

Watch out Swallowing an error in catch without logging or rethrowing hides bugs. Decide at each level whether you can truly recover.

Array methods, immutability and a practice plan

Know what each array method returns and whether it mutates. map, filter, slice and concat return new arrays and leave the original alone. push, pop, splice, reverse and sort change the array in place. sort is the one that catches people twice: with no comparator it compares items as strings, so [10, 9, 1].sort() gives [1, 10, 9]. Pass a comparator such as (a, b) => a - b for numbers.

reduce folds an array into one value. Always supply the initial value: without it an empty array throws a TypeError, and the first element silently becomes the accumulator, which is wrong when you are building an object or a sum of mapped fields.

const totals = orders.reduce((acc, o) => {
  acc[o.type] = (acc[o.type] || 0) + o.amount;
  return acc;
}, {});

Immutable updates avoid surprising shared changes. Use spread to build copies: [...list, item] to add, list.filter(x => x.id !== id) to remove, { ...user, name: "Sam" } to update. Remember that spread and Object.assign copy only one level, so nested objects are still shared. Object.freeze is also shallow. For a true deep copy of plain data, structuredClone is available in modern browsers and Node.

How to practise. Take any snippet in this guide, hide the comment with the answer, and write your prediction first. Use the browser console or Node to confirm, then change one thing (let to var, await removed) and predict again. Keep a personal list of surprises; it becomes your revision sheet.

Practical learning exercises

  • Exercise 1 (DOM & Events): Create a simple HTML page with a button and a list. Write a JS script that adds a new list item with the current timestamp every time the button is clicked.
  • Exercise 2 (Async/Await): Use the fetch API to retrieve data from a public API (like JSONPlaceholder). Parse the JSON and render the titles of the first 5 posts onto the page, handling network errors with try/catch.
  • Exercise 3 (Array Methods): Take an array of product objects (with name, price, and category). Chain .filter() to get only 'electronics', then .map() to extract their names, then .join() to create a comma-separated string.

Practice questions

Question 1 of 20Types

What is the result of typeof null?

Why: A bug preserved since JavaScript's first version — typeof null returns "object". To check for null, use value === null.
Question 2 of 20Array Methods

Which method returns a new array containing only elements for which a callback returns true?

Why: filter returns a new array of all matching elements. find returns only the first match (a single value), map transforms every element, and forEach returns undefined.
Question 3 of 20Functions

What makes arrow functions different from regular functions regarding this?

Why: Arrow functions have no own this — they capture it lexically from the enclosing context, which is exactly why they're preferred for callbacks and event handlers inside classes and methods.
Question 4 of 20Arrays

Which array method creates a new array with the results of calling a function on every element?

Why: map() creates a new array populated with the results of calling a provided function on every element in the calling array.
Question 5 of 20Promises

What does Promise.all() do?

Why: Promise.all() takes an iterable of promises and returns a single Promise that resolves when all of the promises resolve, or rejects with the reason of the first promise that rejects.
Question 6 of 20DOM

Which method is best for selecting a single element by its class name?

Why: `querySelector` returns the first element that matches the CSS selector.
Question 7 of 20Events

What is event delegation?

Why: Delegation takes advantage of event bubbling to handle events on dynamic child elements efficiently.
Question 8 of 20Promises

What is an executing equivalent of `Promise.resolve(5)` using an immediately invoked async function expression (IIFE)?

Why: An executing `async` function implicitly wraps its return value in a Promise, immediately producing a resolved Promise of 5. Simply defining the function (without calling it) only creates a function reference. MDN Web Docs
Question 9 of 20Scope

What is the difference between `let` and `var`?

Why: `let` respects block scope (like inside an if statement), while `var` is hoisted to the function scope.
Question 10 of 20Arrays

Which array method adds an element to the beginning of an array?

Why: `unshift()` adds to the front, `push()` adds to the end.
Question 11 of 20Types

What does `typeof null` evaluate to?

Why: Due to a historical bug in JavaScript, `typeof null` returns `"object"`.
Question 12 of 20Equality

Why is `==` generally avoided in favor of `===`?

Why: `===` checks both value and type, preventing confusing coercions like `0 == false` (which is true).
Question 13 of 20Objects

How do you extract the 'name' property from an object `user` into a variable?

Why: This is object destructuring syntax.
Question 14 of 20Functions

How does the `this` keyword behave in an arrow function?

Why: Arrow functions do not have their own `this` context; they capture it from the surrounding scope.
Question 15 of 20Async

What happens if a `fetch()` request encounters an HTTP 404 error?

Why: `fetch` only rejects on network failure. HTTP errors (404, 500) resolve normally, so you must check `response.ok`.
Question 16 of 20Modules

How do you export a function as the default export of a module?

Why: ES6 modules use the `export default` syntax.
Question 17 of 20Storage

Which storage mechanism is cleared when the page session ends?

Why: sessionStorage data is available only for the duration of the page session.
Question 18 of 20JSON

Which method converts a JS object into a JSON string?

Why: `JSON.stringify()` serializes objects to JSON.
Question 19 of 20Classes

How do you call the constructor of a parent class from a subclass?

Why: The `super()` function calls the parent class constructor.
Question 20 of 20Events

What does `event.preventDefault()` do?

Why: It stops the default action, like preventing a link from navigating or a form from submitting.
