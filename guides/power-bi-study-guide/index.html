Power BI Study Guide: Model, DAX and Reports

Power BI interviews, and Microsoft's PL-300 exam, keep returning to the same four things: preparing data in Power Query, modelling it as a star schema, writing DAX measures, and publishing it securely. This guide walks through each one with examples you can reproduce in Power BI Desktop. It is an unofficial study aid and is not affiliated with Microsoft. Its structure follows the skill areas in Microsoft's PL-300 study guide (skills measured as of April 20, 2026).

What you will learn

By the end you should be able to:

  • Explain how Desktop, the service, semantic models, reports and dashboards fit together
  • Choose between Import and DirectQuery and clean data with Power Query
  • Design a star schema with correct relationships and a date table
  • Write measures with CALCULATE, DIVIDE and time intelligence
  • Build clear, accessible reports and explain how refresh and row-level security work

How the pieces fit together

  • Power BI Desktop is the free Windows application where you connect to data, transform it, build the model and design reports.
  • The Power BI service is the online side: workspaces, sharing, scheduled refresh, dashboards and security.
  • A semantic model is the published model: its tables, relationships and measures. Microsoft renamed what used to be called a dataset to semantic model in 2023; it is a rename only.
  • A report is one or more pages of visuals built on a semantic model. A dashboard exists only in the service: a single canvas of pinned tiles, possibly from several reports.

A typical flow is: get data, transform it in Power Query, model it, build the report, publish, then schedule refresh and secure access.

Prepare data with Power Query

First choose how the data is stored. Both modes are common interview topics:

AspectImportDirectQuery
FreshnessAs of the last refreshQueries the source as users interact
SpeedFast: queries run on in-memory dataDepends on the source's speed
Data sizeMust fit in memory and refresh windowsData stays at the source
Power Query and DAXFull feature setSteps must fold; some DAX is restricted

In DirectQuery, a query or intermediate result of more than one million rows fails unless capacity settings raise the limit. The exam also lists DirectLake, a Microsoft Fabric option; learn it from Microsoft's documentation once you work with Fabric.

Core Power Query skills:

  • Data types. Set them early; a number stored as text breaks sums and sorting.
  • Nulls, errors and inconsistencies. Replace placeholder values such as "N/A" with null, then remove or fix them.
  • Group by, pivot and unpivot. Unpivot turns columns such as Jan, Feb, Mar into Month and Sales rows, the long layout that models and visuals prefer.
  • Merge vs append. Append stacks rows from tables with the same columns. Merge joins tables on a key, like a SQL join.
  • Reference vs duplicate. Duplicate copies a query's steps into an independent query. Reference starts a new query from the original's output, so upstream changes flow through.
  • Query folding. When steps fold, the source runs them as a native query, so less data is moved. Right-click a step and check View Native Query to see whether folding still works.
Load only what you need Remove unused columns and rows in Power Query. It is one of the cheapest performance fixes available.

Model the data: star schema and relationships

Microsoft recommends a star schema. Dimension tables describe things such as products, customers and dates, and filter and group the data. Fact tables store events such as sales and are summarised. Power BI infers the role from the relationship: the 'one' side is a dimension, the 'many' side is a fact table.

Relationship settingWhat to know
CardinalityOne-to-many, many-to-one, one-to-one and many-to-many. The 'one' side must hold unique values, or the refresh fails.
Cross-filter directionSingle or Both. Prefer Single; bi-directional filtering can make results harder to reason about.
Active vs inactiveOnly one active path can exist between two tables. An inactive relationship is used only by USERELATIONSHIP inside a calculation.

Role-playing dimensions. One date table often has to filter sales by order date and by ship date. If you need both at once, Microsoft recommends a separate date table for each role. If not, keep one date table with an inactive relationship and use USERELATIONSHIP in measures.

Date table. Time intelligence needs a date table with unique, contiguous dates and no blanks. Create one with CALENDAR or CALENDARAUTO, or load an existing date dimension, and mark it as a date table.

Date = CALENDARAUTO()

Performance. Remove unnecessary rows and columns, reduce granularity where you can, and use Performance Analyzer and DAX query view to find slow visuals, measures and relationships.

DAX essentials

AspectMeasureCalculated column
EvaluatedAt query time, in the current filter contextRow by row, when data refreshes
Stored in the modelOnly the formulaThe values, which add to model size
Use forTotals, ratios, year-to-date, anything that responds to slicersRow-level attributes you need to slice, filter or relate on
Total Sales = SUM ( Sales[Amount] )

Blue Sales =
CALCULATE ( [Total Sales], 'Product'[Color] = "Blue" )

Margin % = DIVIDE ( [Total Profit], [Total Sales] )

Sales LY =
CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )

Sales YTD = TOTALYTD ( [Total Sales], 'Date'[Date] )
  • Filter context is the set of filters that apply to a calculation: slicers, rows and columns of a visual, and filters from relationships.
  • CALCULATE evaluates an expression in a modified filter context. A filter on a column that is already filtered overwrites that filter, unless you wrap it in KEEPFILTERS. Its Boolean filters can reference columns from only one table and cannot reference measures.
  • Context transition. Inside a row context, CALCULATE converts the current row into filters.
  • Iterators such as SUMX evaluate an expression row by row, then aggregate: SUMX ( Sales, Sales[Quantity] * Sales[Price] ).
  • DIVIDE returns BLANK, or an alternate result you choose, when the denominator is zero.
The classic trap With a slicer on Color = Red, CALCULATE ( [Total Sales], 'Product'[Color] = "Blue" ) still returns Blue sales. The measure's filter overwrites the slicer's filter on the same column.

Build reports that communicate

  • Navigation and exploration: slicers and filters, sync slicers across pages, bookmarks, drillthrough pages, custom tooltips and the Selection pane for layering.
  • Formatting: themes keep a consistent look; conditional formatting highlights values that matter.
  • Analysis tools: reference lines, forecasting, binning and grouping, and AI visuals such as Key influencers. Copilot features appear on the exam's skill list; whether you can use them depends on your licence and capacity.
  • Accessibility: write alt text for visuals, set a sensible tab order, keep contrast high, and never rely on colour alone to carry meaning.

Publish, refresh and secure

You publish from Desktop to a workspace. Workspace roles are Admin, Member, Contributor and Viewer. You can share content through an app, and you can promote or certify content to show which semantic models people should trust.

Refresh. An Import model is refreshed on a schedule. Microsoft's limits are 8 scheduled refreshes a day on shared capacity (Pro) and 48 on Premium per user or Premium and Fabric capacity. Sources that sit on a private network, such as an on-premises database, need a gateway. Power BI turns the schedule off after four consecutive failures, and pauses it after two months with no views of the model's reports or dashboards.

Row-level security (RLS).

  • You define roles in Desktop (Modeling, Manage roles) with DAX filters, publish, then add users or groups to each role in the service.
  • RLS applies to workspace Viewers. Admin, Member and Contributor bypass it because they can edit the model.
  • A person in several roles sees the union of the rows. A person with no matching role sees no rows.
  • RLS filters rows, not columns.
-- static role
[Region] = "West"

-- dynamic role: each user sees rows mapped to their sign-in
[ManagerEmail] = USERPRINCIPALNAME ()

Use Test as role in the service to check what a role sees before you rely on it.

Practical learning exercises

  • Exercise 1 (Power Query). A table has columns OrderID, Region, Jan, Feb and Mar. Some sales cells contain the text "N/A". Set data types, replace "N/A" with null, unpivot Jan to Mar into Month and Sales, and remove null rows. Check: you end with one numeric Sales value per order and month.
  • Exercise 2 (Model). Tables: Sales (OrderID, OrderDate, ShipDate, ProductID, Quantity, Amount), Product (ProductID, Name, Category) and Date (Date, Year, Month). Build a star schema so a visual can show sales by order date and by ship date side by side. Check: Product and Date each filter Sales in a one-to-many relationship, and a second date table (for example Ship Date) has its own active relationship to ShipDate.
  • Exercise 3 (DAX). Write measures for total sales, sales for the same period last year, and year-over-year percentage change. Solution: 
    Total Sales = SUM ( Sales[Amount] )
Sales LY = CALCULATE ( [Total Sales], SAMEPERIODLASTYEAR ( 'Date'[Date] ) )
YoY % = DIVIDE ( [Total Sales] - [Sales LY], [Sales LY] )
  • Exercise 4 (Security). Add a SalesRegion table (Region, ManagerEmail) that filters Sales. Create a role whose filter on SalesRegion is [ManagerEmail] = USERPRINCIPALNAME (), then use Test as role to confirm a manager sees only their region.
  • Exercise 5 (Report). Build a one-page report with a card, a line chart over time, a bar chart by category and a slicer. Add alt text to every visual and check the tab order with the keyboard.

Interview questions

Try answering aloud before you open each one.

What is the difference between Power BI Desktop and the Power BI service?

Desktop is the free Windows application where you connect to data, transform it in Power Query, build the model and design reports. The service is the online environment where you publish, share, schedule refresh, build dashboards and manage security.

Import or DirectQuery: how do you choose?

Import is the default choice: fast, with the full Power Query and DAX feature set, but only as fresh as the last refresh. DirectQuery suits data that is too large to import or must always be current, but performance depends on the source, steps must fold, and queries returning more than one million rows fail unless capacity settings allow it.

What is the difference between a measure and a calculated column?

A measure is evaluated at query time in the current filter context and stores only its formula. A calculated column is computed row by row at refresh and its values are stored in the model. Use measures for totals and ratios, and columns for row-level attributes you need to slice or relate on.

What does CALCULATE do?

It evaluates an expression in a modified filter context. A filter argument on a column that is already filtered overwrites that filter unless you use KEEPFILTERS. With no filter arguments it performs context transition, turning row context into filter context.

Why is a star schema recommended?

Each visual sends a query that filters and groups by dimension columns and summarises fact columns. Dimension tables for filtering and fact tables for summarising match that pattern, which keeps models simpler, smaller and faster than one wide table or deep snowflaked chains.

What is a role-playing dimension and how do you handle it?

One dimension that filters facts in different ways, such as a date table used for order date and ship date. Only one relationship between two tables can be active. Microsoft recommends a separate table per role when you need both at once, or an inactive relationship with USERELATIONSHIP when you do not.

Why do you need a date table?

Time intelligence functions such as TOTALYTD and SAMEPERIODLASTYEAR need a proper date table: unique, contiguous dates with no blanks. Create it with CALENDAR or CALENDARAUTO, or bring in an existing date dimension, and mark it as a date table.

What is the difference between merge and append in Power Query?

Append stacks rows from tables that share columns. Merge joins tables side by side on key columns, with join kinds such as left outer or inner, like a SQL join.

What is the difference between Reference and Duplicate?

Duplicate copies the query and its steps into an independent query. Reference creates a new query that starts from the output of the original, so changes to the original flow into it.

How does row-level security work, and who does it apply to?

You define roles with DAX filter expressions in Desktop (Modeling, Manage roles), publish, then add users or groups to the roles in the service. It applies to workspace Viewers; Admin, Member and Contributor bypass it. A user in several roles gets the union of the rows. It restricts rows, not columns.

What is the difference between a report and a dashboard?

A report is one or more pages of visuals built on a semantic model. A dashboard exists only in the service: a single canvas of pinned tiles, which can come from several reports and models.

A report is slow. How would you investigate?

Use Performance Analyzer to find which visuals are slow and DAX query view to inspect the queries. Then remove unused rows and columns, reduce granularity where possible, move toward a star schema, and review expensive measures and relationships.

Practice questions

Question 1 of 20Basics

In the Power BI service, what is the current Microsoft name for what used to be called a dataset?

Why: Microsoft renamed the dataset content type to semantic model in 2023. It is a rename only; nothing about how models behave changed.
Question 2 of 20Storage modes

Which storage mode keeps a copy of the data in memory, so visuals only show new source data after a refresh?

Why: Import caches data in the model, which is fast and fully featured but only as fresh as the last refresh. DirectQuery sends queries to the source each time.
Question 3 of 20Power Query

You have twelve monthly sales tables with identical columns and want a single long table. Which operation do you use?

Why: Append stacks rows from tables with matching columns. Merge joins tables side by side on a key, like a SQL join.
Question 4 of 20Power Query

You create a Reference of query A, then change a step in query A. What happens to the referenced query?

Why: A referenced query starts from the output of the original, so upstream changes flow through. A Duplicate copies the steps and is independent.
Question 5 of 20Power Query

A table has columns Jan, Feb and Mar, each holding sales. You want columns Month and Sales instead. Which transformation fits?

Why: Unpivot turns column headers into attribute values, giving one row per month. This long layout is what relationships, slicers and measures work best with.
Question 6 of 20Power Query

Why do you want transformation steps to support query folding when the source is a database?

Why: When steps fold, the source does the filtering and shaping. In DirectQuery, steps that cannot fold cause errors or force you to simplify.
Question 7 of 20Modelling

A refresh loads duplicate values into the 'one' side column of a one-to-many relationship. What happens?

Why: The 'one' side must contain unique values. Duplicates there make the whole refresh fail, so clean or de-duplicate the key first.
Question 8 of 20Modelling

In a one-to-many relationship, which side is the dimension table?

Why: Power BI infers table roles from relationships: the 'one' side is a dimension (filters and groups) and the 'many' side is a fact table (events to summarise).
Question 9 of 20Modelling

Sales has both OrderDate and ShipDate related to one Date table. How many of those relationships can be active?

Why: Only one active filter path can exist between two tables. For simultaneous filtering by both dates, Microsoft recommends a separate date table per role.
Question 10 of 20Modelling

Which is a requirement for a date table used for time intelligence?

Why: A date table has one row per date, no gaps, no blanks, and unique values. Mark it as a date table for classic time intelligence.
Question 11 of 20DAX

Which of these is calculated at query time in the current filter context and is not stored row by row in the model?

Why: Measures are evaluated when a visual needs them, in the filter context of that visual. Calculated columns are computed at refresh and stored.
Question 12 of 20DAX

A slicer selects Color = Red. A measure is CALCULATE([Total Sales], 'Product'[Color] = "Blue"). What does the measure return?

Why: A CALCULATE filter on a column overwrites any existing filter on the same column, so the slicer's Red is replaced by Blue.
Question 13 of 20DAX

Which function do you wrap around a CALCULATE filter so that it adds to, rather than overwrites, existing filters on the same column?

Why: KEEPFILTERS keeps the existing filters and intersects them with the new one.
Question 14 of 20DAX

Why prefer DIVIDE([Profit], [Sales]) over [Profit] / [Sales]?

Why: DIVIDE takes an optional alternate result for division by zero and returns BLANK by default, so visuals do not show errors or infinity.
Question 15 of 20DAX

Which function returns the same period in the previous year, for a prior-year comparison?

Why: SAMEPERIODLASTYEAR shifts the current dates back one year. DATESYTD returns the year-to-date dates of the current year.
Question 16 of 20DAX

Revenue is Quantity times Unit Price on each row. Which measure adds this up correctly?

Why: SUM takes a single column. SUMX is an iterator: it evaluates the expression for every row, then adds the results.
Question 17 of 20Reports

Which visual is the usual choice for showing a trend over time?

Why: A line chart shows change across an ordered axis such as dates. Pie charts and treemaps show part-to-whole, and a card shows one number.
Question 18 of 20Reports

Which feature lets a user right-click a data point and jump to a detail page already filtered to that item?

Why: Drillthrough passes the selected item's filter context to a target page. Sync slicers keep slicer selections consistent across pages.
Question 19 of 20Security

A user with the Contributor role in the workspace opens a report on a semantic model that has RLS roles. What do they see?

Why: RLS applies to workspace Viewers. Admin, Member and Contributor can edit the model, so they bypass row-level security.
Question 20 of 20Refresh

A scheduled refresh fails four times in a row. What does Power BI do?

Why: Power BI disables the schedule after four consecutive failures (or an unrecoverable error such as expired credentials). Fix the cause, then re-enable it.

Preparation checklist

  • Explain Import vs DirectQuery and when you would choose each
  • Draw a star schema and say which table is the dimension in each relationship
  • Describe active vs inactive relationships and how role-playing dimensions are handled
  • Write measures using CALCULATE, DIVIDE, SUMX and a time-intelligence function, and explain why a CALCULATE filter overwrites a slicer
  • Describe how RLS is defined, assigned and tested, and which workspace roles bypass it
