Once you are comfortable with the basics, interviews move to how Python actually behaves: lazy iteration, closures, decorators, the class machinery, cleanup with with, and which concurrency model to pick. This guide covers those topics with short examples. Every code block on this page is a complete script that was run on Python 3.13 before publishing. For variables, loops, functions and data structures, start with the Python study guide. This is an unofficial study aid; the Python documentation is the final word.

What you will learn

By the end you should be able to:

  • Write generators and explain why they are lazy and single-use
  • Explain closures and late binding, and write decorators that keep function metadata
  • Use @property, dunder methods and dataclasses, and read a method resolution order
  • Write context managers and chain exceptions correctly
  • Choose between threads, processes and asyncio, and explain the GIL
Version Examples were run on Python 3.13. Details such as the free-threaded build vary by version, so check the docs for yours.

Generators and iterators

A function with yield is a generator function. Calling it does not run the body: it returns a generator, and execution starts when you ask for the first value. At each yield the function is suspended with all of its local state retained.

def squares(n):
    for i in range(n):
        yield i * i

g = squares(3)
print(next(g))     # 0
print(list(g))     # [1, 4]
print(list(g))     # []  (a generator can only be consumed once)

A generator expression, (x * x for x in range(3)), is lazy in the same way, while a list comprehension builds the whole list at once. Laziness lets you work with infinite or very large sequences:

from itertools import islice

def naturals():
    n = 0
    while True:
        yield n
        n += 1

print(list(islice(naturals(), 4)))   # [0, 1, 2, 3]

Functions: closures, decorators and caching

Closures capture variables, not values. All three lambdas below see the final value of i; a default argument binds the value at definition time.

late = [lambda: i for i in range(3)]
bound = [lambda i=i: i for i in range(3)]
print([f() for f in late])    # [2, 2, 2]
print([f() for f in bound])   # [0, 1, 2]

Decorators wrap a function. @wraps copies the original's name and docstring onto the wrapper and adds a __wrapped__ attribute.

from functools import wraps

def counted(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return fn(*args, **kwargs)
    wrapper.calls = 0
    return wrapper

@counted
def add(a, b):
    "Add two numbers."
    return a + b

add(1, 2)
print(add.__name__, add.calls)   # add 1

Mutable default arguments are created once, when the function is defined, and shared by every call:

def bad(x, items=[]):
    items.append(x)
    return items

def good(x, items=None):
    if items is None:
        items = []
    items.append(x)
    return items

print(bad(1))     # [1]
print(bad(2))     # [1, 2]  (the same list is reused)
print(good(1))    # [1]
print(good(2))    # [2]

Caching. functools.lru_cache keeps the most recent calls (128 by default) and needs hashable arguments. functools.cache is lru_cache(maxsize=None), an unbounded cache.

from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(30))               # 832040
print(fib.cache_info().misses)   # 31

Classes: properties, dunder methods, dataclasses and MRO

Properties run code on attribute access while callers keep plain attribute syntax:

class Temp:
    def __init__(self, c):
        self._c = c

    @property
    def c(self):
        return self._c

    @c.setter
    def c(self, v):
        if v < -273.15:
            raise ValueError("below absolute zero")
        self._c = v

    @property
    def f(self):
        return self._c * 9 / 5 + 32

t = Temp(100)
print(t.f)    # 212.0
t.c = 0
print(t.f)    # 32.0

Dunder methods let your class work with operators and built-ins. If you define __eq__ without __hash__, Python sets __hash__ to None, so instances become unhashable.

class Vec:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vec({self.x}, {self.y})"

    def __eq__(self, other):
        return isinstance(other, Vec) and (self.x, self.y) == (other.x, other.y)

    def __add__(self, other):
        return Vec(self.x + other.x, self.y + other.y)

print(Vec(1, 2) + Vec(3, 4))        # Vec(4, 6)
print(Vec(1, 2) == Vec(1, 2))       # True
print(Vec.__hash__)                 # None

Dataclasses. By default @dataclass generates __init__, __repr__ and __eq__. Ordering needs order=True (which requires eq=True). A mutable default such as x: list = [] raises ValueError; use default_factory. With frozen=True, assigning to a field raises FrozenInstanceError, a subclass of AttributeError.

from dataclasses import dataclass, field, FrozenInstanceError

@dataclass
class Item:
    name: str
    qty: int = 0
    tags: list = field(default_factory=list)

print(Item("pen", 2))                      # Item(name='pen', qty=2, tags=[])
print(Item("pen", 2) == Item("pen", 2))    # True

@dataclass(frozen=True)
class Point:
    x: int

p = Point(1)
try:
    p.x = 2
except FrozenInstanceError:
    print("frozen")

Method resolution order. super() follows the MRO of the instance's class. In the diamond below the chain is D, B, C, A, not D, B, A:

class A:
    def who(self):
        return "A"

class B(A):
    def who(self):
        return "B>" + super().who()

class C(A):
    def who(self):
        return "C>" + super().who()

class D(B, C):
    def who(self):
        return "D>" + super().who()

print(D().who())                              # D>B>C>A
print([k.__name__ for k in D.__mro__])        # ['D', 'B', 'C', 'A', 'object']

Context managers

A with statement calls __enter__ at the start and __exit__ at the end, even when the body raises. The shortest way to write one is a generator with @contextlib.contextmanager; put the cleanup in a finally block so it runs on errors.

import contextlib

@contextlib.contextmanager
def tag(log, name):
    log.append("open " + name)
    try:
        yield name
    finally:
        log.append("close " + name)

log = []
try:
    with tag(log, "x"):
        raise RuntimeError
except RuntimeError:
    pass
print(log)    # ['open x', 'close x']

Files are the everyday example: with open(path, "w", encoding="utf-8") as f: closes the file for you. pathlib.Path gives readable path handling:

import tempfile
from pathlib import Path

with tempfile.TemporaryDirectory() as d:
    p = Path(d) / "notes.txt"
    with open(p, "w", encoding="utf-8") as f:
        f.write("a\nb\n")
    print(p.read_text(encoding="utf-8").splitlines())   # ['a', 'b']
    print(p.suffix, p.stem, p.exists())                 # .txt notes True

Errors and exceptions

Create your own exception by subclassing Exception. Use raise ... from ... to keep the original as __cause__. A finally block runs even when the try block returns.

class ValidationError(Exception):
    def __init__(self, field, msg):
        super().__init__(f"{field}: {msg}")
        self.field = field

try:
    raise ValidationError("age", "must be positive")
except ValidationError as e:
    print(e, e.field)          # age: must be positive age

try:
    try:
        int("x")
    except ValueError as e:
        raise RuntimeError("bad config") from e
except RuntimeError as e:
    print(type(e.__cause__).__name__)   # ValueError

def order():
    out = []
    try:
        out.append("try")
        return out
    finally:
        out.append("finally")

print(order())    # ['try', 'finally']
Catch narrowly except Exception does not catch SystemExit or KeyboardInterrupt, which derive from BaseException. A bare except: catches them too, so avoid it.

Concurrency: threads, processes and asyncio

WorkloadUsual choiceWhy
Many network or disk waitsasyncio or threadsThe GIL is released during I/O, so waits overlap
Heavy pure-Python computationMultiple processesOnly one thread runs Python bytecode at a time in a standard build
Blocking call inside async codeasyncio.to_thread()A blocking call would stall the event loop

The GIL is a CPython mechanism ensuring only one thread executes Python bytecode at a time. Some extension modules release it during heavy work such as compression or hashing. Python 3.13 adds an optional free-threaded build (--disable-gil), but the standard build still has the GIL.

asyncio. Calling an async def function only creates a coroutine object; run it with asyncio.run(), await it, or schedule it as a task. asyncio.gather() runs awaitables concurrently and returns results in the order given. By default the first exception propagates and the others keep running; with return_exceptions=True, exceptions are returned in the result list.

import asyncio
import time

async def fetch(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    start = time.perf_counter()
    results = await asyncio.gather(fetch("a", 0.2), fetch("b", 0.2), fetch("c", 0.2))
    print(results, round(time.perf_counter() - start, 1))   # ['a', 'b', 'c'] 0.2

asyncio.run(main())

Three 0.2-second waits finish in about 0.2 seconds, not 0.6, because they overlap. The exact timing depends on your machine.

Practical standard-library tools

from collections import Counter, defaultdict
from itertools import chain, groupby

print(Counter("banana").most_common(1))        # [('a', 3)]

groups = defaultdict(list)
for key, value in [("x", 1), ("y", 2), ("x", 3)]:
    groups[key].append(value)
print(dict(groups))                            # {'x': [1, 3], 'y': [2]}

print(list(chain([1], [2, 3])))                # [1, 2, 3]

words = sorted(["ant", "bee", "ape"], key=lambda s: s[0])   # groupby needs sorted input
print({k: list(v) for k, v in groupby(words, key=lambda s: s[0])})   # {'a': ['ant', 'ape'], 'b': ['bee']}

Practical learning exercises

  • Exercise 1 (generator). Write a generator evens(limit) that yields the even numbers below limit. Solution: 
    def evens(limit):
    for n in range(0, limit, 2):
        yield n

print(list(evens(9)))   # [0, 2, 4, 6, 8]
  • Exercise 2 (decorator). Write a decorator counted that counts how many times a function is called and keeps the function's name. Solution: the counted decorator in the functions section above; check add.calls and add.__name__.
  • Exercise 3 (dataclass). Define an Item with a name, an integer quantity defaulting to 0, and a list of tags that is not shared between instances. Solution: the Item dataclass above; confirm that Item("a").tags is not Item("b").tags.
  • Exercise 4 (context manager). Write a context manager that records "open" and "close" even if the body raises. Solution: the tag context manager above.
  • Exercise 5 (asyncio). Run three 0.2-second tasks so the total is about 0.2 seconds. Solution: the asyncio.gather example above.

Interview questions

Try answering aloud before you open each one.

What is the difference between an iterable, an iterator and a generator?

An iterable can produce an iterator (it has __iter__). An iterator produces values one at a time with __next__ and raises StopIteration when finished. A generator is an iterator created by a function containing yield, or by a generator expression, and it keeps its local state between values.

What is a closure?

A function that remembers variables from the scope where it was defined. The variable is captured, not its value at that moment, which is why lambdas created in a loop all see the loop variable's final value unless you bind it with a default argument.

How does a decorator work?

@decorator above a function is shorthand for func = decorator(func). The decorator returns a wrapper that runs extra code around the original. Use functools.wraps on the wrapper so the name, docstring and __wrapped__ attribute are preserved.

Why is a mutable default argument a bug?

Default values are evaluated once, when the def statement runs, so one list or dict is shared by every call. Use None as the default and create the object inside the function.

When would you use a dataclass instead of a plain class?

When the class mainly holds data. @dataclass generates __init__, __repr__ and __eq__ from annotated fields, and options such as frozen=True and order=True add immutability and ordering. Use field(default_factory=...) for mutable defaults.

What is the method resolution order (MRO)?

The order Python searches classes for an attribute. It is available as Class.__mro__ and follows C3 linearisation. super() follows the MRO of the instance's class, not simply the parent of the current class.

How does a with statement work?

The object's __enter__ runs at the start and its __exit__ runs at the end, even if the body raises. You can write one as a class, or as a generator with @contextlib.contextmanager where code after the yield (in a finally block) is the cleanup.

What does raise ... from ... do?

It chains exceptions: the new exception's __cause__ is set to the original, so tracebacks show both. It is the usual way to translate a low-level error into a clearer one without losing the original.

Threads, processes or asyncio?

Use asyncio or threads for I/O-bound work, because waiting overlaps. Use multiple processes for CPU-bound pure Python on multiple cores, because of the GIL. Python 3.13 also offers an optional free-threaded build, configured with --disable-gil, but the standard build still has the GIL.

What is the GIL?

The global interpreter lock: a CPython mechanism that lets only one thread execute Python bytecode at a time. It is released during I/O, and some extension modules release it during heavy computation such as compression or hashing.

What does async def actually give you?

Calling it returns a coroutine object that does nothing until awaited, passed to asyncio.run(), or scheduled as a task. Blocking calls inside a coroutine block the whole event loop, so use asyncio.to_thread() for blocking I/O.

How do lru_cache and cache differ?

lru_cache(maxsize=128) keeps the 128 most recent calls by default, and arguments must be hashable. functools.cache is lru_cache(maxsize=None): an unbounded cache that never evicts, so it is smaller and faster but can grow without limit.

Practice questions

Question 1 of 20Generators

You call a generator function. When does its body start running?

Why: Calling a generator function only creates a generator object. Execution starts when one of its methods, such as next(), is called, and it runs to the first yield.
Question 2 of 20Generators

After a generator has been fully consumed with list(g), what does a second list(g) return?

Why: A generator is its own iterator and can only be consumed once. After it is exhausted, further iteration yields nothing.
Question 3 of 20Generators

Why use a generator expression instead of a list comprehension when summing a very large range?

Why: A list comprehension builds the whole list first. A generator expression yields one value at a time, which keeps memory use small.
Question 4 of 20Closures

What does [f() for f in [lambda: i for i in range(3)]] return?

Why: Closures capture the variable i, not its value at the time. By the time the lambdas are called, i is 2. Bind it with a default argument (lambda i=i: i) to get [0, 1, 2].
Question 5 of 20Decorators

What does functools.wraps do inside a decorator?

Why: Without wraps, the decorated function reports the wrapper's name and loses its docstring. wraps also adds a __wrapped__ attribute pointing to the original.
Question 6 of 20Defaults

What is wrong with def add(x, items=[]): items.append(x); return items?

Why: Default values are evaluated once when the function is defined. Use items=None and create the list inside the function.
Question 7 of 20functools

What is the default maxsize of functools.lru_cache?

Why: lru_cache keeps up to 128 recent calls by default. maxsize=None disables eviction, which is what functools.cache does.
Question 8 of 20functools

What happens if you call an lru_cache-decorated function with a list argument?

Why: The cache is a dictionary keyed by the arguments, so positional and keyword arguments must be hashable. Lists are not.
Question 9 of 20Dataclasses

Which methods does @dataclass generate by default?

Why: The defaults are init=True, repr=True and eq=True. Ordering methods are generated only with order=True.
Question 10 of 20Dataclasses

What happens with a dataclass field written as x: list = [] ?

Why: @dataclass raises ValueError for unhashable defaults such as a list. default_factory calls a zero-argument callable to build a fresh value for each instance.
Question 11 of 20Dataclasses

You assign to a field of a frozen dataclass instance. What is raised?

Why: frozen=True makes assignment raise FrozenInstanceError, which subclasses AttributeError.
Question 12 of 20Dataclasses

What does @dataclass(order=True, eq=False) do?

Why: The docs state that if order is true and eq is false, a ValueError is raised.
Question 13 of 20Data model

A class defines __eq__ but not __hash__. What happens to hashing of its instances?

Why: Defining __eq__ without __hash__ sets __hash__ to None. Define both if instances must be used in sets or as dict keys.
Question 14 of 20Inheritance

Given class D(B, C), where B and C both inherit from A, what is D's method resolution order?

Why: C3 linearisation keeps D first, then its bases in the order listed, and puts the shared base A after both B and C. That is why super() chains B, then C, then A.
Question 15 of 20Classes

What does the @property decorator let you do?

Why: A property exposes a method as an attribute. With a setter, you can validate on assignment while callers keep using obj.x = value.
Question 16 of 20Context managers

A function decorated with @contextlib.contextmanager yields inside try/finally, and the with-body raises an exception. What happens to the finally block?

Why: The exception is re-raised inside the generator at the yield, so the finally block runs for cleanup. The exception then propagates to the caller.
Question 17 of 20Concurrency

What does the CPython GIL guarantee?

Why: The Python glossary defines the GIL as the mechanism ensuring only one thread executes Python bytecode at a time, at the cost of much of the parallelism of multi-core machines.
Question 18 of 20Concurrency

Why can threads still speed up I/O-bound work despite the GIL?

Why: The glossary says the GIL is always released when doing I/O. Threads waiting on the network or disk can overlap. For CPU-bound pure Python, the docs point to multiple processes.
Question 19 of 20asyncio

You call an async def function without await. What do you get?

Why: Calling a coroutine function only creates a coroutine object. Run it with asyncio.run(), await it, or schedule it as a task. An unawaited coroutine triggers a RuntimeWarning.
Question 20 of 20asyncio

With asyncio.gather(a, b) and the default return_exceptions=False, task a raises. What happens?

Why: By default the first raised exception propagates, and the other awaitables keep running. With return_exceptions=True, exceptions are collected in the result list. TaskGroup cancels the remaining tasks.
