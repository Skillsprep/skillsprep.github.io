Git

Git Study Guide: Commands and Concepts

Published Jul 30, 2026 Last reviewed Oct 18, 2026 7 min read By the SkillPrep Editorial Team (Expert Practitioners & Curriculum Designers)

Unofficial study resource. Written independently of any exam provider, employer or software vendor.

Interviews and skills tests focus on everyday version-control workflows. Questions often present a situation ("you committed to the wrong branch") and ask for the correct command sequence.

Core workflow commands

git status              # what's changed / staged
git add file.txt        # stage a file
git commit -m "msg"     # commit staged changes
git log --oneline       # compact history
git diff                # unstaged changes
git diff --staged       # staged vs last commit

Know the three areas cold: working directory → git add → staging area → git commit → repository.

Undoing things — a favorite topic

SituationCommand
Discard unstaged changes to a filegit restore file.txt (or git checkout -- file.txt)
Unstage a file (keep changes)git restore --staged file.txt
Amend the last commitgit commit --amend
Move branch pointer back one commit (keep changes staged)git reset --soft HEAD~1
Revert a pushed commit safelygit revert <sha>
Key distinction reset rewrites history (dangerous after push); revert creates a new commit that undoes changes (safe for shared history).

Merge vs rebase

Both combine branches, but differently:

  • Merge — creates a merge commit, preserves true history. Safe for shared branches.
  • Rebase — replays your commits on top of another branch, producing linear history. Never rebase commits others have pulled.

The golden rule: rebase local, merge shared.

Practical learning exercises

  • Exercise 1 (Branching): In a local repo, create a new branch called feature-login. Make a change to a file, stage it, commit it with a descriptive message, and switch back to main.
  • Exercise 2 (Merging & Conflicts): Intentionally create a merge conflict. Modify the same line of a file in both main and a test branch. Attempt to merge the branch into main, resolve the conflict markers in your editor, and complete the merge.
  • Exercise 3 (History): Use git log --oneline --graph to view your history. Then use git revert to safely undo your last commit by creating a new inverse commit.

Practice questions

Question 1 of 20Basics

Which command shows the difference between your working directory and the staging area?

Why: Plain git diff compares working tree to the index (staging area). --staged compares the index to the last commit instead.
Question 2 of 20Undoing

A commit has already been pushed to a shared branch, and you need to undo it without rewriting history. What do you use?

Why: revert adds a new commit that undoes the target commit — safe for shared history. reset rewrites history and would break teammates' repos on their next pull.
Question 3 of 20Branching

What does git checkout -b feature do?

Why: The -b flag creates the branch and immediately checks it out — equivalent to git branch feature followed by git checkout feature. Modern Git also offers git switch -c feature for the same job.
Question 4 of 20Branching

Which command creates a new branch and switches to it immediately?

Why: git checkout -b <branch> is a shortcut that creates the branch and immediately checks it out. git switch -c <branch> also does this.
Question 5 of 20History

How do you discard all uncommitted changes in your working directory?

Why: git reset --hard resets the index and working tree to match the last commit, discarding all uncommitted local changes.
Question 6 of 20Basics

What command initializes a new Git repository?

Why: `git init` creates the hidden .git folder that tracks repository history.
Question 7 of 20Staging

What is the purpose of the staging area (index) in Git?

Why: The staging area allows you to craft precise commits rather than committing all changed files at once.
Question 8 of 20Committing

Which command records staged changes to the repository history?

Why: `git commit` captures a snapshot of the staged changes.
Question 9 of 20Remote

What does `git clone` do?

Why: `git clone` downloads the entire repository, including its history, to your local environment.
Question 10 of 20Branching

How do you create and switch to a new branch in one command?

Why: `git switch -c` (newer) or `git checkout -b` (older) perform both actions simultaneously.
Question 11 of 20History

Which command shows the status of files (modified, staged, untracked)?

Why: `git status` provides an overview of the working tree and staging area.
Question 12 of 20Remote

What is the difference between `git fetch` and `git pull`?

Why: `git pull` is essentially `git fetch` followed immediately by `git merge`.
Question 13 of 20Undoing

You made a typo in your last commit message. How can you fix it without creating a new commit?

Why: `git commit --amend` replaces the most recent commit with a new one containing updated changes/messages.
Question 14 of 20Merging

What happens during a merge conflict?

Why: Conflicts occur when identical lines are changed differently. Git inserts markers for you to resolve manually.
Question 15 of 20Rebasing

How does `git rebase` differ from `git merge`?

Why: Rebasing moves the base of a branch to a new commit, keeping history clean but rewriting commit IDs.
Question 16 of 20Stashing

You need to switch branches but have half-finished work you don't want to commit yet. What command should you use?

Why: `git stash` temporarily shelves changes so you can work on something else.
Question 17 of 20Configuration

How do you set your global Git username?

Why: The `git config` command manages settings. `--global` applies it to all repos for the user.
Question 18 of 20Files

What is the purpose of a `.gitignore` file?

Why: It prevents temporary files, build artifacts, or uncommitted secrets from being accidentally committed. Note: adding an already-tracked file to .gitignore does not remove it from tracking or history. Official Reference
Question 19 of 20Inspection

Which command shows the exact line-by-line differences of uncommitted changes?

Why: `git diff` compares the working directory with the staging area or last commit.
Question 20 of 20Undoing

Which command safely undoes a published commit by creating a new commit with the opposite changes?

Why: `git revert` is safe for shared history because it doesn't rewrite or delete past commits.

Final tips

  • Practice the "wrong branch" scenario: you committed on the wrong branch → git branch newbranch, then git reset --hard HEAD~1, then git switch newbranch
  • Know git stash / stash pop for parking unfinished work
  • Understand .gitignore purpose — preventing untracked build artifacts and secrets from being committed.
  • Security Warning: .gitignore does not automatically remove files already tracked by Git. If you accidentally commit a secret, adding it to .gitignore later is not safe. You must remove the secret from tracking (e.g., git rm --cached), immediately rotate/revoke the exposed credentials, and consider cleaning the repository history.
