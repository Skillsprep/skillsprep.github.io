Python Fundamentals: Study Guide + Practice Quiz

14 min read 20 Questions Published Sep 3, 2026 Reviewed Oct 18, 2026

Unofficial study resource. Written independently of any exam provider, employer or software vendor.

Python interviews and skills tests usually probe core language knowledge rather than frameworks. A solid grip on built-in data types, iteration, error handling, and a few intermediate features like comprehensions and decorators covers most of it.

Topics to know cold

These are the areas worth being able to explain from memory:

  • Lists, dicts, tuples, sets — mutability, methods (append, get, set operations)
  • List & dict comprehensions — reading and writing them
  • String methods — split, join, strip, replace, slicing
  • Exceptions — try/except/else/finally flow
  • Functions — *args/**kwargs, default arguments, lambda, scope (global)
  • Decorators — basic understanding of @wrapper syntax
  • OOP basics — __init__, self, inheritance, super()

The classic mutable default argument trap

This pattern is a favourite in interviews and tests. What does this print?

def add(item, basket=[]):
    basket.append(item)
    return basket

print(add("apple"))
print(add("banana"))

Answer: ['apple'] then ['apple', 'banana']. The default list is created once when the function is defined and shared across calls. The safe pattern is def add(item, basket=None): with a fresh list inside.

Remember Default argument values are evaluated once at function definition time — not on each call. This applies to any mutable default.

Comprehension patterns

Learn to read comprehensions left-to-right: [expression for item in iterable if condition]

# squares of even numbers 0-9
[x**2 for x in range(10) if x % 2 == 0]
# swap keys/values
{v: k for k, v in prices.items()}

Names, objects and mutability: what assignment really does

In Python a variable is a name that points to an object, not a box that holds a value. Writing b = a does not copy anything; it makes a second name for the same object. For immutable objects such as numbers, strings and tuples this never matters, because you cannot change the object in place. For mutable objects such as lists, dicts and sets it matters a lot, because a change made through one name is visible through every other name.

a = [1, 2, 3]
b = a            # same object, two names
b.append(4)
print(a)         # [1, 2, 3, 4]

c = a.copy()     # new list, same elements
c.append(5)
print(a)         # [1, 2, 3, 4]  (unchanged)

Use == to ask "do these have equal values?" and is to ask "are these the exact same object?". Reserve is for singletons, mainly x is None. Comparing numbers or strings with is can appear to work because the interpreter sometimes reuses objects, but that is an implementation detail you must not rely on.

Copies come in two depths. list.copy(), list(x) and slicing x[:] make shallow copies: the outer list is new, but the inner objects are shared. For a list of lists, use copy.deepcopy. A related trap is grid = [[0] * 3] * 3, which builds three references to the same inner list; write [[0] * 3 for _ in range(3)] instead.

Augmented assignment is another subtle spot. For a list, x += [1] mutates the existing object, while x = x + [1] builds a new list and rebinds the name. This difference shows up when a list is passed into a function: the first form changes the caller's list, the second does not.

Interview reasoning Python passes references to objects by value (often called "pass by assignment"). Inside a function, parameter names start as aliases of the caller's objects. Mutating the object is visible outside; rebinding the parameter name is not.

Scope and the LEGB rule

When Python meets a name it searches four scopes in order: Local (the current function), Enclosing (any outer functions), Global (the module) and Built-in (names like len). The first match wins. This is why a local variable called list or max hides the built-in, and why later calls such as list("abc") suddenly fail.

The rule that surprises beginners: if a function assigns to a name anywhere in its body, that name is local for the whole function. So this fails:

count = 0

def bump():
    count += 1      # UnboundLocalError: count is local here

def bump_ok():
    global count
    count += 1

Reading a global needs no declaration; rebinding it does. Inside a nested function, use nonlocal to rebind a variable of the enclosing function. Prefer returning values or using a small class over reaching for global, because hidden shared state makes code hard to test.

Closures capture variables, not values, and look the value up when the inner function runs. That produces the well-known late-binding surprise:

funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])        # [2, 2, 2]

funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])        # [0, 1, 2]

The fix binds the current value as a default argument at definition time.

A practical way to debug scope problems is to ask three questions in order. Is the name assigned anywhere in this function? If so, it is local everywhere in it. If not, which enclosing function or module defines it? Finally, did something earlier in the file rebind it to a different object, such as a loop variable reusing the name of a function? Printing locals() inside the function shows exactly which names Python treats as local.

Common mistake Naming a variable after a built-in (id, list, sum, input) works at first, then breaks later code that expects the built-in. Pick descriptive names instead.

Iterators and generators

An iterable is anything you can loop over; it has an __iter__ method that returns an iterator. An iterator has __next__, returns one item at a time, and raises StopIteration when it runs out. A for loop is just sugar: it calls iter() once, then calls next() repeatedly until StopIteration. A list is iterable but not itself an iterator.

A generator function is the easy way to write an iterator. Any function containing yield returns a generator object when called, and its body does not run until you ask for the first value. Each next() runs the body up to the next yield, then pauses with all local state preserved.

def countdown(n):
    while n > 0:
        yield n
        n -= 1

g = countdown(3)
print(next(g))      # 3
print(list(g))      # [2, 1]
print(list(g))      # []  exhausted

Two consequences matter in practice. First, generators are single-use: once exhausted they yield nothing, so looping a second time silently gives an empty result. If you need several passes, build a list or recreate the generator. Second, generators are lazy, so they hold one item in memory at a time. A generator expression such as sum(x * x for x in range(1000000)) avoids building a million-item list.

Comprehension or loop? Use a comprehension when you are building one new collection from one iterable with a simple filter. Switch to a regular loop when you need several statements, early exit with break, or side effects like printing. A comprehension with two nested for clauses and an if is usually harder to read than the loop it replaces.

Debugging tip If a generator-based result is unexpectedly empty, check whether something earlier already consumed it, for example a list(g) or a for loop over the same object.

Exceptions, dataclasses and type hints

Good exception handling is about being specific. Catch the narrowest exception you can actually handle, and keep the try block small so you know which line failed. A bare except: also catches KeyboardInterrupt and SystemExit, which is almost never what you want; except Exception is the broadest reasonable choice. The else block runs only when no exception occurred, and finally runs in every case, which makes it the right place for cleanup (though a with statement is usually neater).

def read_age(text):
    try:
        age = int(text)
    except ValueError as err:
        raise ValueError("age must be a whole number") from err
    else:
        return age

The raise ... from err form keeps the original error attached as the cause, which makes tracebacks far easier to debug. Inside an except block, a plain raise re-raises the current exception unchanged. Prefer "ask forgiveness" (try, then handle the error) when failure is rare, and a simple if check when the failure case is common and cheap to test.

The dataclasses module removes the boilerplate from classes that mainly store data. Decorating a class with @dataclass generates __init__, __repr__ and __eq__ from the annotated fields. A mutable default such as a list is rejected with a ValueError, which neatly prevents the shared-default bug; use field(default_factory=list) instead.

from dataclasses import dataclass, field

@dataclass
class Order:
    id: int
    items: list[str] = field(default_factory=list)
    note: str | None = None

Type hints (list[str], and str | None on Python 3.10+) document intent and let tools like mypy or your editor catch mistakes. The interpreter itself does not enforce them at runtime: passing a string where int is annotated will still run.

Virtual environments, practice plan and glossary

A virtual environment is an isolated folder holding its own Python interpreter link and installed packages, so one project's dependencies cannot break another's. The standard-library way to make one:

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install requests
python -m pip freeze > requirements.txt

Calling python -m pip guarantees pip belongs to the interpreter you are running. A common mistake is installing packages while no environment is active, then wondering why the editor cannot find them. Keep the environment folder out of version control and commit requirements.txt instead so others can recreate it.

How to practise. Predict before you run: write down what each snippet in this section prints, then check. Use id(x) and is in the REPL to watch aliasing happen. Rewrite one of your own loops as a generator and compare memory by eye on a large range. Finally, deliberately trigger UnboundLocalError, StopIteration and a dataclass default error once each so the messages look familiar in an interview or a real bug.

Practice questions

Question 1 of 20Data Types

Which of these is immutable?

Why: Tuples cannot be modified after creation. Note that they can be used as dictionary keys and set members only if all their elements are hashable (e.g. a tuple containing a list cannot be a dictionary key). Lists, dicts, and sets are all mutable.
Question 2 of 20Exceptions

In a try/except/else/finally block, which part runs only when no exception is raised?

Why: else executes only if the try block completes without raising. finally always runs (exception or not), and except runs only when an exception occurs.
Question 3 of 20Functions

What does *args allow in a function definition?

Why: *args collects extra positional arguments into a tuple. Collecting keyword arguments into a dict is **kwargs — the two are frequently confused in questions.
Question 4 of 20Data Structures

Which of the following is true about sets in Python?

Why: Sets in Python are unordered collections of unique elements. They do not allow duplicates and do not support indexing.
Question 5 of 20Functions

What is the purpose of *args in a function definition?

Why: *args allows a function to accept a variable number of positional arguments, which are packed into a tuple.
Question 6 of 20Lists

What is the output of `[1, 2, 3] * 2`?

Why: Multiplying a list by an integer repeats the elements.
Question 7 of 20Dictionaries

How do you safely get a value from a dictionary without risking a KeyError?

Why: `dict.get()` returns None (or a specified default) if the key is missing.
Question 8 of 20Strings

Which method is used to remove whitespace from both ends of a string?

Why: `strip()` removes leading and trailing characters (spaces by default).
Question 9 of 20Control Flow

What does the `pass` statement do?

Why: `pass` is a placeholder when a statement is syntactically required but no code needs to execute.
Question 10 of 20List Comprehensions

Which comprehension creates a list of even numbers from 0 to 9?

Why: The `if` condition filters the elements produced by the `for` loop.
Question 11 of 20Functions

What does `**kwargs` do in a function definition?

Why: `**kwargs` collects extra keyword arguments into a dictionary.
Question 12 of 20Modules

How do you import only the `pi` constant from the `math` module?

Why: The `from module import name` syntax imports a specific attribute.
Question 13 of 20File I/O

What is the best practice for opening a file to ensure it gets closed automatically?

Why: The `with` statement acts as a context manager, automatically closing the file even if exceptions occur.
Question 14 of 20OOP

What is the purpose of the `__init__` method in a class?

Why: `__init__` is the constructor method called when a new instance is created.
Question 15 of 20Exceptions

Which block is executed regardless of whether an exception occurred?

Why: The `finally` block is always executed, making it useful for cleanup tasks.
Question 16 of 20Data Types

Which of the following is mutable?

Why: Sets are mutable collections, while tuples, strings, and integers are immutable.
Question 17 of 20Iteration

What function is used to iterate over a sequence alongside an index?

Why: `enumerate()` yields pairs containing a count (from zero) and a value yielded by the iterable argument.
Question 18 of 20Scope

If a variable is defined inside a function, its scope is:

Why: Variables assigned within a function are local to that function unless declared otherwise.
Question 19 of 20Virtual Environments

Why use a virtual environment?

Why: Virtual environments keep packages separate for different projects.
Question 20 of 20Formatting

What does the 'f' signify in `f'Hello {name}'`?

Why: F-strings provide a concise, readable way to embed expressions inside string literals.
